How LifeGuard AI Works

The complete 9-step intelligent personal safety workflow.

1

User Opens LifeGuard AI

User launches the LifeGuard AI Android application on their smartphone.

2

User Manually Starts Monitoring

The user explicitly taps "START MONITORING". Audio monitoring is never started automatically without user consent.

Privacy Rule: Monitoring only runs when manually activated by the user.
3

Ambient Sound Level Monitoring

The application measures surrounding sound levels in decibels (dB SPL) locally in memory.

4

~90 dB Analysis Trigger

If estimated sound level reaches approximately 90 dB or above, deeper audio analysis is triggered.

Important: 90 dB itself is NOT an emergency. It only triggers deeper analysis.
5

Short Audio Segment Capture

The app captures a short 3.0-second PCM audio buffer (48,000 samples @ 16 kHz Mono).

6

Local Preprocessing & Mel Spectrogram

Audio is transformed locally using Hann window, Radix-2 Cooley-Tukey FFT, and 64 Mel filterbanks into a Log-Mel Spectrogram matrix [1, 92, 64, 1].

7

TensorFlow Lite Classification

Our custom on-device neural network (75.2 KB) classifies the sound into: Environmental, Human Normal, or Human Distress.

8

Safety Confirmation Screen (10s Countdown)

If Human Distress confidence reaches the configured threshold (≥ 70%), the app prompts: "Possible emergency detected. Are you safe?" with a 10-second countdown.

9

Emergency Activation or Cancellation

• YES, I'M SAFE: Incident is cancelled and saved as safe.
• NO, HELP or 10-second timeout: Emergency workflow activates immediately, alerting connected contacts with GPS coordinates.

On-Device Machine Learning Architecture

Custom-trained neural network operating 100% on-device inside the Android app.

🔬 Neural Network Pipeline

16 kHz Mono Audio PCM Buffer (3.0 seconds, 48,000 samples)
               │
               ▼
   AudioFeatureExtractor.java:
   • Hann Window (N=1024, Hop=512)
   • Radix-2 Cooley-Tukey FFT (513 frequency bins)
   • 64 Triangular Mel Filterbanks (0 Hz – 8000 Hz)
   • Log-Mel Spectrogram Matrix [1, 92, 64, 1]
               │
               ▼
   TensorFlow Lite Classifier (lifeguard_audio_classifier.tflite - 75.2 KB):
   • Conv2D (16 filters, 3x3) + BatchNorm + ReLU + MaxPool(2x2)
   • Conv2D (32 filters, 3x3) + BatchNorm + ReLU + MaxPool(2x2)
   • Conv2D (64 filters, 3x3) + BatchNorm + ReLU + GlobalAveragePooling2D
   • Dense (64, ReLU, Dropout 0.3)
   • Dense (3, Softmax Output)
               │
               ▼
   Output Probabilities:
   [0] environmental
   [1] human_normal
   [2] human_distress

Explicit ML Boundaries

• No Speaker Identification: The model does NOT identify who is speaking.
• No Owner Voice Matching: It does NOT determine whether the sound belongs to the phone owner or a stranger.
• No Cloud AI: Zero API keys or cloud AI services are used for sound classification.

Model Specification

• Model Size: 75.2 KB (TensorFlow Lite)
• Quantization: Float32 weights & activations
• Classification Target: Distinguish environmental sounds, normal speech, and distress screams
• Decision Threshold: Confidence ≥ 0.70 triggers safety confirmation

Privacy & Data Handling

Transparent data practices grounded in privacy-first engineering.

Our Privacy Commitments

• On-Device Audio Processing: All acoustic feature extraction and classification run strictly inside the Android device using TensorFlow Lite. Raw ambient audio is never streamed to any external cloud server.

• Temporary In-Memory Buffers: When ~90 dB is reached, audio is stored in a temporary 3-second memory buffer and cleared after inference.

• Location Data: GPS coordinates are captured only during active emergency events (manual SOS or confirmed distress) and transmitted solely to your connected emergency contacts.

• Account Security: Passwords are encrypted using bcrypt salt hashing, and API authentication utilizes JSON Web Tokens (JWT).
